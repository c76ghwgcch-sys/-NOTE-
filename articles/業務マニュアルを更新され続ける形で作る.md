# 業務マニュアルを、更新され続ける形で作る

## いま、こんな場面で止まっていませんか
「この作業、マニュアルにしておいて」と言われました。前にも誰かが作ったマニュアルはあります。でも開いてみると、画面が今と違う。書いてある手順どおりにやると、途中で止まる。結局、みんなマニュアルを見ずに詳しい人に聞いている。また同じものを作っても、半年後には誰も開かなくなるのではないか。この記事は、作ったあとも書き直され続けるマニュアルを作るための手順です。

## この記事が向いていない人
- 会社に、マニュアルの決まった書き方や管理の担当部署がある人
- 動画で手順を残したい人(この記事は文章と画像のマニュアルを扱います)
- 1回きりの作業を記録したい人

## 全体像：4ステップで終わります
1. どの作業をマニュアルにするか決める
2. 実際にやりながら、1手順1動作で書く
3. 他の人に、マニュアルだけを見てやってもらう
4. 更新の担当と時期を決めて、置き場所を決める

マニュアル1本あたり、作るのに2〜3時間が目安です。

| ステップ | 終わったときに、手元にあるもの |
|---|---|
| 1 | マニュアルにする作業の一覧と、作る順番 |
| 2 | 1手順1動作で書いた下書き |
| 3 | 他の人が、口を出されずに最後までできたマニュアル |
| 4 | 更新の担当・時期・置き場所のルール |

マニュアルが使われなくなる原因は、書き方よりも **作ったあと** にあります。この記事では、書き方と同じくらい、作ったあとの仕組みに時間を使います。

## 有料部分に入っているもの
- 1人しかやらない業務／複数人で回す業務／外部に渡す業務で、何を変えるか
- マニュアルにする作業の選び方
- 1手順1動作の書き方と、画面の切り取り方
- 更新が止まらない仕組みの作り方
- そのまま使える書式3つ：手順書のひな形／更新履歴の表／置き場所とファイル名のルール
- できあがったかどうかの確認方法

ーーー ここから有料 ーーー

## 状況の分かれ方：誰が使うかで、書き方が変わります

### Aの場合：自分1人しかやらない業務
いちばん多く、いちばん危ないパターンです。あなたが休んだり異動したりした瞬間に、誰もできなくなります。
読むのは「未来の誰か」です。**その会社に来たばかりの人でもできるか** を基準に書きます。社内の略語には、必ず説明をつけます。

### Bの場合：複数人で回している業務
人によってやり方が少しずつ違う状態になりがちです。マニュアルを作る前に、**どのやり方を正式にするか** をチームで決めます。
決めずに書くと、書いた人のやり方だけが残り、他の人が使わなくなります。

### Cの場合：外部(取引先・委託先)に渡す業務
社内でしか見られない画面やフォルダは、相手からは見えません。
- 社内システムの画面を貼らない(相手が使う画面だけ載せる)
- 判断が必要な場面では、「この場合は○○へ連絡」と連絡先を書く
- 渡す前に、社外に出してよい情報か、上司に確認する

## ステップ1：どの作業をマニュアルにするか決める
全部の作業をマニュアルにする必要はありません。次の3つに当てはまるものから作ります。
1. 月1回以下しかやらない作業(手順を忘れる)
2. 間違えると取り返しがつかない作業(お金・締切・社外への送信)
3. 自分しかできない作業

逆に、毎日やっていて誰でもできる作業は、後回しにします。

### 作る順番の決め方
作業を書き出したら、3つの条件に当てはまる数を数えます。
| 作業 | 月1回以下 | 間違えると大変 | 自分しかできない | 数 |
|---|---|---|---|---|
| 年度末の予算の締め | ○ | ○ | ○ | 3 |
| 月次集計の出力 | ○ | ○ | | 2 |
| 毎朝のメール確認 | | | | 0 |

数が多い作業から作ります。3つとも当てはまる作業は、今月中に作ってください。

## ステップ2：実際にやりながら、1手順1動作で書く

### 1手順1動作とは
1つの番号に、1つの動作だけを書く書き方です。

悪い例：
> 3. システムにログインして、月次メニューから集計を出力する

良い例：
> 3. ブラウザで社内システムを開く
> 4. 右上の「ログイン」を押す
> 5. 左のメニューから「月次」を押す
> 6. 「集計を出力」ボタンを押す

動作を分けると、どこで止まったかが分かります。

### 書くタイミング
思い出しながら書かず、**実際にその作業をやる日に、横に画面を開いて書きます。** 思い出しで書くと、慣れている人ほど手順を飛ばします。

### 画面の切り取り
Windowsでは「Windowsキー + Shift + S」で、画面の一部を切り取れます【要確認：Windowsのバージョンで動きが変わる】。Macでは「Command + Shift + 4」です。
切り取った画像には、押す場所に赤い四角を付けます。画像だけで押す場所が分かれば、文字を読まない人にも伝わります。

[ここに体験]

### 画像に写してはいけないもの
画面を切り取るときは、次のものが写っていないか確認します。
- お客さまの名前や住所、電話番号
- 社員の個人の情報
- パスワードやログインの情報

写っている場合は、画像を編集してその部分を塗りつぶします。とくにCの場合(外部に渡す)は、渡す前にもう1度見てください。

## ステップ3：他の人に、マニュアルだけを見てやってもらう
これがいちばん大事な工程で、多くの人が飛ばします。
1. その作業をやったことがない人に頼む
2. 横で見ている間、**自分は一言も口を出さない**
3. 相手の手が止まった場所に、印をつける
4. 印のついた場所を書き直す

手が止まった場所は、あなたにとって「当たり前」すぎて書かなかった場所です。

## ステップ4：更新の担当と時期を決めて、置き場所を決める
マニュアルが使われなくなる原因は、**更新されないこと** です。更新されない理由は、「誰が、いつ直すか」が決まっていないからです。

### 更新の仕組み
- 担当：その作業を、いちばん最近やった人
- 時期：その作業をやった日に、違っていたところを直す
- 記録：書式2の更新履歴に、日付と直したところを1行書く

「定期的に見直す」と決めても、ほぼ実行されません。**作業をやった日に直す** と決めると、作業の流れの中で直せます。

### 置き場所
置き場所は1か所にします。同じマニュアルが2か所にあると、どちらが新しいか分からなくなります。書式3のルールで決めます。

[ここに体験]

### マニュアルの一覧を作る
マニュアルが3本を超えたら、一覧を1枚作ります。
| 作業名 | いつやるか | 最終更新日 | 更新の担当 |
|---|---|---|---|
| 月次集計の出力 | 毎月5営業日目 | 2026/○/○ | ○○ |

一覧は、マニュアルと同じフォルダのいちばん上に置きます。最終更新日を並べると、長く直されていないマニュアルがひと目で分かります。

## つまずきやすい箇所と、その対処
| つまずき | 対処 |
|---|---|
| 書き始めると、例外の話ばかりになる | 例外はマニュアルの最後に「こんなときは」としてまとめる。本文は、いちばん多い流れだけ書く |
| 画面が変わって、画像が古くなる | 画像の下に、撮った日付を書く。古い画像を見つけた人が、すぐ気づける |
| 誰も更新履歴を書かない | マニュアルの最初の行に「最終更新日」を書く。日付が古いと、開いた人が気にする |
| 作業の担当者がマニュアルを直す時間がないと言う | 直すのは、違っていた1行だけでよいと伝える。全体を書き直す必要はない |
| 長くなりすぎて、読まれない | 1つのマニュアルは1つの作業だけ。作業が2つあるなら、マニュアルを2つに分ける |

## そのまま使える書式3つ

### 書式1：手順書のひな形(Aの場合は、略語の説明欄を必ず埋める)
```
# 【作業名】月次集計の出力
最終更新：2026/○/○(更新した人：○○)

## この作業について
- いつやるか：毎月5営業日目
- かかる時間：約30分
- 終わったら誰に渡すか：○○課長
- 略語の説明：「月次」＝その月の数字をまとめたもの

## 手順
1. ブラウザで社内システムを開く
2. 右上の「ログイン」を押す
3. 左のメニューから「月次」を押す
(画像：押す場所に赤い四角。撮影日 2026/○/○)

## 終わったかの確認
- 出力したファイルの名前が「月次_2026xx.xlsx」になっている

## こんなときは
- 「権限がありません」と出たら：○○さんに連絡
```

### 書式2：更新履歴の表(Bの場合は、決めたやり方の変更もここに書く)
| 日付 | 直した人 | 直したところ | 理由 |
|---|---|---|---|
| 2026/○/○ | ○○ | 手順4のボタン名 | システムの画面が変わったため |
| 2026/○/○ | △△ | 「こんなときは」に1件追加 | 新しいエラーが出たため |

### 書式3：置き場所とファイル名のルール(Cの場合は、社外用の置き場所を分ける)
```
置き場所：共有フォルダ ¥マニュアル¥(部署名)¥
ファイル名：【作業名】_最終更新日.docx
例：【月次集計の出力】_20261025.docx

ルール
- 同じマニュアルを別の場所に置かない
- 古い版は「old」フォルダへ移す(消さない)
- 社外に渡すものは ¥マニュアル¥社外用¥ に分けて置く
```

## 終わったかどうかの確認方法
- [ ] 1つの番号に、1つの動作だけが書いてある
- [ ] やったことがない人が、口を出されずに最後までできた
- [ ] 最初の行に、最終更新日と更新した人が書いてある
- [ ] 更新の担当と時期が、チームで決まっている
- [ ] 置き場所が1か所だけになっている

## この手順が終わった人が、次に困ること
マニュアルができると、次に困るのは **新しく来た人が、マニュアルを見ずに聞いてくる** ことです。マニュアルがあることを知らない、どれを見ればいいか分からない、という状態です。マニュアルの一覧と、聞かれたときの答え方は、別の記事で書きます。
